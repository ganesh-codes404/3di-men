# Mitsugen Route B: neural 3D model research (done on the Intel MacBook Air)

Static research only — no model weights downloaded, no neural inference run on
this machine, per this task's own hardware rules (8GB RAM, Intel, no CUDA, and
free disk space was down to 8.0GB at the time of writing — not enough headroom
for a multi-GB ML stack even if the hardware supported running one).

## Evidence labels used below

- **Verified** — confirmed by fetching the model's own official repo/README directly.
- **Published** — stated in the model's own paper/announcement, not independently reproduced.
- **Estimated** — inferred from related/official figures, not a direct statement.
- **Unverified** — only found in secondary blogs/mirrors; the official source didn't confirm it.
- **Rejected** — ruled out below, with the reason stated.

## Why TripoSR is the shortlisted pick, not just the first one checked

1. **License clarity**: MIT, confirmed directly from the official repo, for both code and weights. Every other option either doesn't fit the VRAM budget, has an unresolved/conditional commercial license, or has unverified license terms.
2. **VRAM headroom**: ~6GB stated for the CLI path, leaving real margin under this hardware's expected 8GB — unlike TripoSG, which states 8GB as its *minimum*, with no stated margin at all.
3. **Maintenance**: confirmed real, recent push activity (June 2026) and growing stars — the strongest maintenance signal of any candidate checked here.
4. **It needs a text→image step**, but that step is **not a new risk** — this exact repo already has working, tested code for it (`sd-turbo` in `kaggle/hunyuan3d_baseline.ipynb`), just run remotely there. The adapter built this round reuses that same technique locally instead.

## What remains genuinely unverified (stated plainly, not guessed)

- TripoSR's actual peak VRAM on an RTX 4060 specifically (the 6GB figure is the project's own stated default, not measured on this exact GPU).
- Whether `torchmcubes` compiles cleanly against whatever CUDA/driver version is actually installed on the RTX 4060 laptop (version mismatches here are the single most common real-world failure point for this class of tool, per TripoSR's own README caution about matching CUDA major versions).
- Real generation time and output quality on a 4060 specifically, for any candidate.
- Whether InstantMesh's weight license permits the use case here at all (not checked — rejected primarily on the VRAM/maintenance signals, with the license question left explicitly open rather than assumed either way).

None of the above can be resolved without the RTX 4060 laptop itself.
